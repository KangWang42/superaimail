# AI 设置

AI 是可选增强。关闭后，所有邮件连接、索引、规则和手动收发继续运行。

## 连接兼容服务

进入「设置 → AI 助手」：

1. 填写服务商提供的兼容接口基础地址，如 `https://model.example.org/v1`。应用会在后面加 `/chat/completions`，不要重复填写完整请求路径。
2. 填写你有权限使用的模型 ID。该字段没有默认的商业模型，直接按服务商提供的名称填写。
3. 填写 API Key。保存后不会在界面回显；以后留空表示保留原值。
4. 开启 AI，选择自动整理时机和每日调用上限，保存。
5. 打开一封邮件，点击「AI 提炼要点」。返回要点即表示接口调用与响应格式可用。

服务需要支持 Chat Completions 格式的 `messages`、`model`、`temperature` 与 `max_tokens`，并返回 `choices[0].message.content`。部分模型不支持这些参数，或使用其他专用 API，需选择兼容模式或兼容代理。本项目不代表服务商承诺所有模型可用。

## 使用本机模型

本机兼容接口可以使用回环 HTTP，例如已有的 Ollama 服务：

```text
接口地址：http://127.0.0.1:11434/v1
模型名称：填写本机已安装、支持指令与 JSON 输出的模型
API Key：本机无鉴权时可留空
```

这里的“本机”指运行 SuperAIMail 后台的设备。容器内的 `127.0.0.1` 指容器自身；跨容器或局域网访问应通过 HTTPS 反向代理提供接口。应用不自动下载模型或安装模型运行时。

先用一封普通邮件测试摘要，再开启自动分类。小模型的 JSON 格式和中文判断能力可能影响分类效果。对文件归属、发件人身份和截止时间应保留人工核对。

## 自动整理与额度

- 「新邮件到达时」按小批次合并处理，最多等待约 90 秒；不是每次打开界面都调用模型。
- 「每天定时」「每三天定时」按设置时间整理，时间以北京时间计算。
- 每日上限按北京时间日期计数，包含自动整理与手动操作。失败请求也计入调用，应用的调用计数不等于服务商计费 token。
- 上限为 0 时暂停模型调用。关闭 AI 后，不再启动新的 AI 工作；已经发出的请求仍可能完成。
- 「立即整理」执行已有邮件的分类、收集候选检查与命名整理。

## 哪些内容会发送给模型

摘要、回复和翻译会使用当前邮件的主题、发件人和受长度限制的正文；分类使用一批邮件的摘要与附件名称。附件收集判断可能使用受限的 XLSX 文本预览。不会执行表格公式或上传整个数据目录。

邮件内容是不可信输入。系统提示要求模型忽略正文中冒充用户或要求改变任务的指令；模型结果仍可能不准确。草稿不会自行发出，任务归属有冲突时留待确认。

## 常见错误

| 提示 | 处理 |
|---|---|
| HTTP 401 / 403 | 检查 API Key、模型权限和服务商限制 |
| HTTP 404 | 检查基础地址，避免重复 `/v1` 或 `/chat/completions` |
| HTTP 429 | 查看服务商额度或速率限制，降低自动调用量 |
| 回复格式无法识别 | 选择支持指令和 JSON 输出的模型，查看服务商兼容性 |
| 连接超时 | 在运行后台的设备上核对网络，必要时选择代理出口 |
| 每日调用已达上限 | 等待次日或修改设置；收件不受影响 |
